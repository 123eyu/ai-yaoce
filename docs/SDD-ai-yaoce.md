# AI 遥测（ai-yaoce）软件设计说明书

版本：0.1
日期：2026-10-04
状态：开发基线

## 1. 背景与目标

本项目基于现有 macOS 原生版与 Windows/Electron 版监控程序，重构为独立的公开项目 `ai-yaoce`。安装后的产品名称为“AI 遥测”，保留现有 logo，删除 Mirasim 作为监控来源，保留 Codex 与 Claude，并新增：

- zcodex
- DSH DeepSeek
- Qwen Codex
- Kimi Codex

产品只做本地读取和本地聚合，不向服务端上传任何用户数据。

## 2. 非目标

本轮不实现以下能力：

1. 不主动调用官方额度、余额或账号接口。
2. 不做代理、抓包、网络拦截或发送探测请求。
3. 不绕过登录、不破解客户端加密、不读取明文密钥。
4. 不删除或改写 Codex、Claude、国产客户端原有数据目录。
5. 不把“没有本地上传证据”解释为“客户端绝对没有上传”。

## 3. 产品范围

### 3.1 统一来源

```text
codex
claude
zcodex
dsh-deepseek
qwen-codex
kimi-codex
```

来源可单独启用、停用、刷新和隐藏。停用只停止 AI 遥测读取，不删除来源文件。

### 3.2 渠道状态

每个来源独立输出：

```text
official-subscription  本地证据表明是官方订阅
official-api           本地证据表明是官方 API
relay                  本地配置或日志表明使用中转
unknown                发现来源但证据不足
not-configured         没发现本地配置或日志
```

渠道识别使用本地配置、日志、进程参数、端点域名和客户端标识的组合证据。单一名称、默认值或历史缓存不能直接决定渠道。

### 3.3 订阅与用量字段

字段均为 optional：

- `quotaWindows`：5 小时、7 天或客户端实际提供的自定义窗口。
- `balance`：金额、币种、读取时间，仅 DSH 等确有本地余额证据时展示。
- `planExpiry`：套餐到期时间，仅官订本地证据存在时展示。
- `usage`：本地日志聚合的请求、token、模型和最近活动。
- `warnings`：过期、字段不完整、来源不可读等限制。

没有字段就不显示，不显示为 0，也不复用其他来源数据。

## 4. 双端架构

### 4.1 Node/Electron

Node 后端负责来源适配、文件扫描、去重、聚合、渠道识别、审计脱敏与快照输出；Electron 只通过现有安全 IPC 读取快照和写入用户明确的本地设置。

建议模块：

```text
node/source-registry.mjs       来源注册、启停和能力声明
node/local-adapters.mjs        六来源本地文件适配器
node/channel-detector.mjs      官订/官方API/中转/未知识别
node/privacy-audit.mjs         被动证据提取与脱敏
node/desktop-backend.mjs       统一快照编排
desktop/ui.js                  来源、渠道、订阅与审计展示
```

### 4.2 Swift/macOS

Swift 复用 Node 端的字段语义，保持原生面板体验。`MonitorSource` 改为六来源，`Store` 负责来源启停与快照，`Model` 增加渠道、余额、套餐和审计结构，`PanelView`/`WindowCard` 展示统一状态。

macOS 不读取 Windows 专用路径；所有路径探测器必须按平台隔离。

### 4.3 应用身份与路径

统一替换：

- 产品显示名：`AI 遥测`
- 仓库名：`ai-yaoce`
- Electron app id：`local.aiyaoce.monitor`
- 应用数据目录：`ai-yaoce`
- macOS Application Support 子目录：`ai-yaoce`
- Windows 启动项、快捷方式、安装包前缀：`AI 遥测` / `ai-yaoce`

旧版路径只做可选、只读迁移发现，不作为新版本默认写入路径。

## 5. 数据契约

双端内部快照统一为：

```json
{
  "version": "2.0.0",
  "updatedAt": "ISO-8601",
  "fixture": false,
  "sources": {
    "codex": {
      "source": "codex",
      "enabled": true,
      "availability": "active",
      "channel": "official-subscription",
      "account": { "id": "local-id", "name": "local label" },
      "quotaWindows": [],
      "balance": null,
      "planExpiry": null,
      "usage": {},
      "privacyAudit": { "items": [], "confidence": "low" },
      "warnings": []
    }
  }
}
```

凭据、token、完整请求正文、提示词、代码正文、完整个人路径不得进入该快照。

### 5.1 审计证据

```json
{
  "kind": "endpoint|local-log|client-declaration|field-observation",
  "label": "可读描述",
  "value": "脱敏后的值",
  "confidence": "high|medium|low",
  "observedAt": "ISO-8601",
  "path": "相对路径"
}
```

审计结果只能描述本地观察到的事实或明确标记“无法判断”。

## 6. 来源适配顺序

### P0：基线与品牌

1. 移除 Mirasim 来源枚举、标签、入口和专属额度卡。
2. 新增六来源 registry 与统一快照骨架。
3. 更换产品名、app id、安装脚本、数据目录和文档标识。
4. 保留 logo，保证旧客户端目录不被改写。

### P1：现有可靠来源

1. 把 Codex、Claude 现有本地日志读取迁移到 registry。
2. 为官订/官方 API/中转/未知增加渠道状态。
3. 只在本地有证据时显示 5 小时、7 天、套餐到期。
4. 保留已有成本和本地统计，但移除 Mirasim 计价语义。

### P2：国产来源

每个来源独立完成：

1. 路径、配置键、日志字段现场核验。
2. 本地活动与渠道识别。
3. 可用的余额、套餐、窗口和用量字段。
4. 空状态、警告、测试夹具和回归用例。

顺序：`zcodex` → `dsh-deepseek` → `qwen-codex` → `kimi-codex`。没有真实本地证据的字段保持隐藏。

### P3：账号与审计

1. 账号列表只记录本地安全引用、展示名、来源和最近观察时间。
2. 账号切换按适配器能力动态显示，切换前备份、切换后本地验证、失败恢复。
3. 审计区显示脱敏端点、可见元数据、日志证据和未知项。
4. 提供清除本地审计缓存和停用来源的操作。

### P4：发布

1. macOS 通用构建、Windows x64 构建。
2. 离线测试、UI smoke、路径检查、敏感信息扫描。
3. 新仓库准备、README、许可证和安装说明。
4. 用户明确要求后再创建公开 GitHub 仓库、推送代码和发布安装包。

## 7. 设置与交互

- 来源列表支持启用/停用，不支持任意输入路径直接读取；路径由适配器白名单控制。
- 官订没有账号时隐藏账号切换；有账号但字段不可读时只显示账号存在和不可读提示。
- 中转只显示已脱敏的端点/来源标签，不展示令牌。
- 审计中“未知”是正常状态，不使用红色错误样式误导用户。
- 空来源必须显示下一步：启用来源、登录客户端或等待本地产生日志。

## 8. 测试计划

### Node

- registry 六来源枚举、启停、未知来源拒绝。
- 快照序列化不得包含 token、提示词、代码正文和完整用户路径。
- 渠道识别的正例、反例和证据不足场景。
- 5 小时/7 天/余额/到期字段缺失时隐藏而不是填 0。
- 审计脱敏、相对路径和稳定排序。
- 旧日志与新快照不混源、不重复计数。

### macOS

- Swift 编译与预览夹具覆盖六来源。
- 来源切换、停用、空状态、审计展开和账号入口条件。
- 通用二进制 arm64/x86_64、路径和 bundle 信息检查。

### Windows/Electron

- IPC 只暴露快照、刷新、设置和本地审计清除，不暴露任意文件读取。
- smoke 覆盖六来源标签、空状态、审计脱敏和设置持久化。
- NSIS 安装路径、快捷方式、卸载脚本和用户数据目录均为 `ai-yaoce`。

## 9. 回滚

- 每个来源适配器可独立禁用，不影响主程序。
- 新版本默认不删除旧数据；出现问题可关闭新来源并恢复旧安装包。
- 品牌迁移只影响新版本写入路径，旧应用和旧路径保留，便于人工恢复。
- 发布前保留构建产物、校验值和测试报告；不改写旧 Git 历史。

## 10. 风险与处理

| 风险 | 处理 |
|---|---|
| 国产客户端格式不稳定 | 适配器独立、字段 optional、没有证据就隐藏 |
| 官方订阅数据只在服务端 | 不主动请求，显示不可读并保留本地用量 |
| 本地日志包含敏感内容 | 只读取字段名/摘要，审计前脱敏，不写原文 |
| 旧路径迁移误伤 | 只读发现，用户确认后复制必要配置，不自动删除 |
| 账号切换失败 | 切换前备份，验证失败自动恢复 |
| 公开仓库误带个人信息 | 发布前扫描作者名、远端、二维码、个人路径、密钥和构建产物 |

## 11. 完成定义

只有在以下证据全部具备时，才称为第一版完成：

1. 两端构建与核心测试通过。
2. Mirasim 不再作为 UI 来源、默认路径或产品品牌出现。
3. 六来源可启停，Codex/Claude 现有本地统计不回归。
4. 官方信息按证据显示，缺失字段隐藏。
5. 隐私审计全程本地、脱敏、无主动网络请求。
6. 新仓库发布前完成敏感信息扫描和用户确认。
