# 模型可用性监测 SDD（2026-10-04）

## 已确认需求
- Windows / Mac设置增加独立模型监测，总开关默认关闭；开启才允许发测试请求。
- 默认600秒、30秒超时、测试口令`Reply 1`、普通模型8输出token；均可修改。
- 模型数量不设业务上限，批量一行一个；单模型启停/删除，最大并发2，不重叠，不补发离线期间积压。
- 每个目标由来源标签、完整请求URL、协议、模型、凭据组成；同名模型不同线路独立。
- 支持Chat Completions、Responses、Anthropic Messages；不猜中转路径，由用户填写完整端点。

## 安全与节流
- 不自动读取用户现有凭据，不发聊天历史/工具/附件；只发送指定短口令。
- HTTPS或明确本机loopback HTTP；禁URL用户密码/query/fragment，不跟随重定向，防凭据跨站泄漏。
- Mac凭据配置存Keychain；Windows通过safeStorage加密落盘。读写失败明确报错，不静默退化明文。
- 总开关关闭立即取消队列与请求；设置保存取消旧请求，旧结果不得覆盖新配置。
- 失败指数退避至最多1小时，401/403暂停至用户重新启用或手动检查；429遵循Retry-After。
- 保存无关设置保留身份未变目标的暂停和下次计划，不因保存额外扣费；正在执行的旧请求取消并标“已取消”。间隔修改对下一次完成后的计划生效。
- 手动检测也必须总开关已开启，不因编辑/启动界面暗中发请求；单目标最多一个在途请求。
- 无法确认真实日志的“端点+凭据+模型”完整身份时不跳过测试，避免把同名不同线路误判成功；近期调用跳过暂不猜测实现。

## 状态和费用
- 显示待检测/检测中/可用/超时/限流/鉴权失败/模型不存在/请求不兼容/服务错误/网络失败/未确认。
- 仅“2xx且有有效文本”判可用；token预算不足/仅推理无文本判未确认，不进行加价自动重试。
- 可选低推理模式；Chat使用max_completion_tokens及reasoning_effort=low，Responses设置reasoning.effort=low；Anthropic关闭额外思考，若模型不支持则标请求不兼容。
- 使用结果附时间、耗时、下次检测时间、过期标记。默认仅普通模式，不假设所有模型支持相同预算。
- 当前运行期单独累计请求/token；无usage标用量未知，手工输入/输出单价估算费用，cache与特殊计费不当实账。退出重新启动清零，配置保留。
- 不把探测结果注入正常会话账本；若中转自身日志记录探测，原日志统计可能包含，界面明确说明。

## 实现与验收
- Node纯逻辑引擎+主进程加密存储/IPC+设置页；Swift独立逻辑/Keychain/URLSession+设置视图。
- 无模型数量上限但大量模型轮询完成时间可能超过间隔；后台仅应用运行时生效。
- 本地模拟响应测试：默认不请求、2并发、取消、退避、重定向、usage、空结果/429/401、配置无效不覆盖。
- 界面夹具验证添加/保存/恢复、关闭不请求；真实上游探测不作为开发验收。
- 版本1.9.0，测试后提交私库，双平台构建验收；不替用户开启检测。
